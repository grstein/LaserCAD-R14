# LCV-090 — Windows MSI installer build

- **Status**: Ready
- **Phase**: 8
- **Depends on**: LCV-087, LCV-089
- **Suggested agent**: implementer-rust
- **Suggested model**: sonnet
- **Implementation**: —

## Problem

A laser-cutter operator on Windows needs a one-click installer for LaserCAD v2: a `.msi`
they can download, double-click, and run from the Start Menu — no Rust toolchain, no
`git clone`, no command-line setup. Without a Windows packaging artifact every Windows
user who wants to drive LaserGRBL from LaserCAD v2 is blocked: the project only
publishes Linux binaries and "build from source" is not an operator workflow. This
demand produces a committed WiX source file and a PowerShell build script that together
generate a standards-compliant Windows MSI installer deposited in `dist/`.

## Scope

- New file `wix/main.wxs` — a WiX Toolset v3 source file, tracked by git, generated
  once via `cargo wix init` and then hand-edited to satisfy the acceptance criteria.
  It is the sole WiX source file for the installer.
- New file `scripts/build-msi.ps1` — a self-contained PowerShell script, tracked by
  git, runnable as `.\scripts\build-msi.ps1` from the repo root on any Windows 10/11
  x86-64 host that has Rust 1.88, WiX Toolset v3 (`candle.exe` + `light.exe` on
  `PATH`), and `cargo-wix` installed (`cargo install cargo-wix`).
- The script first runs `cargo build --release` to produce
  `target\release\lasercad.exe`, then runs `cargo wix --no-build --nocapture` to
  compile and link the WiX source into an MSI, then copies the result to
  `dist\lasercad-x86_64.msi`.
- `VERSION` is derived exclusively by `cargo-wix` reading `[package].version` from
  `Cargo.toml`; it must not be hardcoded anywhere in `wix/main.wxs` or
  `scripts/build-msi.ps1`.
- The installed application layout: `lasercad.exe` at
  `%ProgramFiles%\LaserCAD\lasercad.exe`; a Start Menu shortcut at
  `%ProgramData%\Microsoft\Windows\Start Menu\Programs\LaserCAD\LaserCAD.lnk`;
  no registry entries beyond the MSI standard uninstall key.
- `wix/main.wxs` commits a stable `UpgradeCode` GUID (randomly generated by the
  implementer once; never regenerated).
- `wix/main.wxs` enables `MajorUpgrade` semantics so installing a newer MSI removes
  the previous installation automatically.
- New file `assets/icon.ico` — a Windows `.ico` file converted from
  `assets/icon-256.png`, tracked by git. WiX and the Start Menu shortcut reference
  this file. LCV-088 replaces the placeholder icon artwork; `wix/main.wxs` references
  the file by path and requires no edits when the content changes.
- `dist/` is already gitignored by LCV-085 (AC#11); this demand must not remove that
  entry. Build intermediates under `target\wix\` are already excluded by the existing
  `target/` gitignore entry. No additional `.gitignore` changes are needed.
- No new Rust source files or `Cargo.toml` dependency additions are introduced;
  `cargo-wix` and WiX Toolset v3 are external build-time tools.

## Out of scope

- NSIS-based installer — MSI via WiX Toolset v3 is the chosen format; NSIS is not
  evaluated.
- macOS `.dmg` or `.pkg` packaging — LCV-091.
- Linux packaging — LCV-085 (AppImage), LCV-086 (`.deb`).
- CI pipeline integration of the MSI build step — LCV-092.
- Code-signing the MSI or `lasercad.exe`.
- ARM64 or 32-bit (`i686`) Windows targets — x86-64 only.
- A desktop shortcut — the Start Menu entry is sufficient for v0.1.0.
- Production icon artwork — LCV-088. A placeholder `.ico` converted from
  `assets/icon-256.png` is acceptable for this demand.
- Uploading the MSI as a GitHub Release asset — LCV-089 covers the 0.1.0 Linux
  release; a future demand handles Windows release asset upload.
- Per-user (non-admin) installation — per-machine only for v0.1.0.
- WiX v4 / Burn bootstrapper — WiX Toolset v3 only.

## Acceptance criteria

1. `wix/main.wxs` exists and is tracked by git:
   ```
   git ls-files wix/main.wxs
   ```
   returns `wix/main.wxs`.

2. `scripts/build-msi.ps1` exists and is tracked by git:
   ```
   git ls-files scripts/build-msi.ps1
   ```
   returns `scripts/build-msi.ps1`.

3. The first three directive/executable lines of `scripts/build-msi.ps1` are exactly
   (blank lines and `#`-comments before them are permitted):
   ```powershell
   #Requires -Version 5.1
   $ErrorActionPreference = 'Stop'
   Set-StrictMode -Version Latest
   ```

4. `scripts/build-msi.ps1` contains no hardcoded version string. Confirm by reading
   the script: no string literal matching the pattern `\d+\.\d+\.\d+` appears outside
   of comments; the version is derived entirely from `cargo-wix`'s reading of
   `Cargo.toml`.

5. Running `.\scripts\build-msi.ps1` from the repo root on a Windows 10/11 x86-64
   host with Rust 1.88 (via `rust-toolchain.toml`), WiX Toolset v3 on `PATH`
   (`candle.exe`, `light.exe`), and `cargo-wix` installed produces
   `dist\lasercad-x86_64.msi`. The script exits with code 0.

6. After installation on a clean Windows 10/11 x86-64 VM via
   `msiexec /i dist\lasercad-x86_64.msi /qn`, the following PowerShell assertion
   returns `True`:
   ```powershell
   Test-Path "$env:ProgramFiles\LaserCAD\lasercad.exe"
   ```
   The installed binary is a valid 64-bit Windows PE (`Get-Item` must not throw; file
   size must be > 0).

7. After installation, a Start Menu shortcut exists at:
   ```
   %ProgramData%\Microsoft\Windows\Start Menu\Programs\LaserCAD\LaserCAD.lnk
   ```
   Verify with:
   ```powershell
   Test-Path "$env:ProgramData\Microsoft\Windows\Start Menu\Programs\LaserCAD\LaserCAD.lnk"
   ```
   returns `True`.

8. After uninstallation via `msiexec /x dist\lasercad-x86_64.msi /qn` (exit code 0),
   `%ProgramFiles%\LaserCAD\` no longer exists and the Start Menu shortcut is removed.

9. `wix/main.wxs` contains an `UpgradeCode` attribute with a well-formed GUID matching
   the pattern `\{[0-9A-F]{8}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{4}-[0-9A-F]{12}\}`
   (uppercase hex, braces included). Verify by reading the file:
   ```powershell
   Select-String -Path wix/main.wxs -Pattern 'UpgradeCode'
   ```
   The match line must contain a GUID in the format above.

10. `wix/main.wxs` contains a `<MajorUpgrade>` element. Verify:
    ```powershell
    Select-String -Path wix/main.wxs -Pattern 'MajorUpgrade'
    ```
    returns at least one match.

11. `wix/main.wxs` contains `Manufacturer="LaserCAD contributors"` and
    `Name="LaserCAD"` on the `<Product>` element. Verify by reading the file:
    ```powershell
    Select-String -Path wix/main.wxs -Pattern 'Manufacturer="LaserCAD contributors"'
    Select-String -Path wix/main.wxs -Pattern 'Name="LaserCAD"'
    ```
    both return matches.

12. `assets/icon.ico` exists, is tracked by git:
    ```
    git ls-files assets/icon.ico
    ```
    returns `assets/icon.ico`, and the file is a valid Windows ICO format (the first
    two bytes are `0x00 0x00`, bytes 3–4 are `0x01 0x00` — the ICO magic — verifiable
    with `Format-Hex assets/icon.ico | Select-Object -First 1`).

13. The script is idempotent: running `.\scripts\build-msi.ps1` a second time on an
    already-built tree completes without error and regenerates
    `dist\lasercad-x86_64.msi`. The script removes any pre-existing
    `dist\lasercad-x86_64.msi` before building so stale artifacts cannot accumulate.

14. `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, and
    `cargo test --all` all exit 0 after any changes introduced by this demand. No Rust
    source changes are expected; this AC guards against accidental breakage.

## Notes

### cargo-wix and WiX Toolset v3

`cargo-wix` (crates.io: `cargo-wix`) is a Cargo subcommand wrapping WiX Toolset v3
(`candle.exe` + `light.exe`). It reads `[package]` fields from `Cargo.toml`
(name, version, description, authors) and substitutes them into the `.wxs` template at
build time, eliminating hardcoded version strings.

**Install the tools:**
```powershell
# WiX Toolset v3 — pre-installed on GitHub Actions `windows-latest` runners.
# Local install: https://github.com/wixtoolset/wix3/releases

cargo install cargo-wix
```

**Initialise the WiX source file (one-time, done by implementer):**
```powershell
cargo wix init
```
This creates `wix/main.wxs`. The implementer then edits it to satisfy the ACs
(UpgradeCode, MajorUpgrade, icon reference, Start Menu shortcut).

**Build command sequence inside `scripts/build-msi.ps1`:**
```powershell
cargo build --release
cargo wix --no-build --nocapture
```
`cargo wix` places the MSI at `target\wix\lasercad-VERSION-x86_64.msi`. The script
locates this file with `Get-ChildItem target\wix\*.msi | Select-Object -Last 1` (or
equivalent) and copies it to `dist\lasercad-x86_64.msi`.

### UpgradeCode GUID stability

The `UpgradeCode` GUID is the identity of the product family across all versions.
Once committed it must never change: changing it breaks in-place upgrades for all
existing installations. Generate a new GUID once via PowerShell:
```powershell
[Guid]::NewGuid().ToString('B').ToUpper()
```
Paste the result into `wix/main.wxs`; that value is permanent for LaserCAD v2.

### ICO icon conversion

WiX and Windows shortcuts require an `.ico` file. Convert the existing placeholder
`assets/icon-256.png` to `assets/icon.ico` using any available tool:

```powershell
# ImageMagick (if available):
magick convert assets/icon-256.png -define icon:auto-resize=256,128,64,48,32,16 assets/icon.ico

# Or use the .NET System.Drawing API (no external dependency):
Add-Type -AssemblyName System.Drawing
$bmp = [System.Drawing.Bitmap]::FromFile("$PWD\assets\icon-256.png")
$icon = [System.Drawing.Icon]::FromHandle($bmp.GetHicon())
$fs = [System.IO.File]::OpenWrite("$PWD\assets\icon.ico")
$icon.Save($fs); $fs.Close()
```

Commit `assets/icon.ico` as a tracked git artifact. Reference it from `wix/main.wxs`
via a relative path (`assets\icon.ico`). LCV-088 replaces the artwork; no WiX changes
are needed since the reference is by path.

### MajorUpgrade WiX v3 element

The minimal WiX v3 element for major upgrade handling:
```xml
<MajorUpgrade DowngradeErrorMessage="A newer version of LaserCAD is already installed." />
```
Place it inside the `<Product>` element. This causes the Windows Installer to remove
the previous installation automatically when a newer version is installed.

### MSI vs NSIS

MSI via WiX Toolset v3 is the chosen format:
- MSI is natively handled by `msiexec.exe` on all supported Windows versions; no
  additional runtime.
- MSI provides atomic install/uninstall/upgrade semantics.
- WiX Toolset v3 is pre-installed on GitHub Actions `windows-latest` runners.
- `cargo-wix` automates the boilerplate from `Cargo.toml`, eliminating version
  drift between the binary and the installer metadata.

NSIS produces a setup.exe with a custom installer runtime; the uninstall/upgrade
behaviour is non-standard and requires more script maintenance. Rejected.

### `dist/` gitignore on Windows

`dist/` is already gitignored by LCV-085 (AC#11). The `.gitignore` entry uses the
forward-slash form `dist/` which git on Windows honours correctly (git normalises path
separators). No new entries are needed.

### Relation to LCV-092 (CI matrix)

LCV-092 integrates `scripts/build-msi.ps1` into the CI matrix as a `build-msi` job on
a `windows-latest` runner. This demand only establishes the script and WiX source file;
CI integration is explicitly out of scope here.

### release profile (LCV-087)

`Cargo.toml` carries `strip = true`, `lto = true`, `codegen-units = 1`,
`opt-level = 3`, and `panic = "abort"` in `[profile.release]` after LCV-087 ships.
`strip = true` removes debug information from the PE binary. No release-profile changes
are needed for this demand.
